# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Bun is the package manager (`bun.lock`); Netlify builds with `bun run build`.

- `bun run dev` — Astro dev server (http://localhost:4321)
- `bun run build` / `bun run preview`
- `bun run lint` / `bun run lint:fix` — ESLint (ignores `src/components/ui/`, which is generated by shadcn)
- `bun run test` — Vitest once; `bun run test:watch` to watch
- Single test: `bunx vitest run src/tests/footer.test.ts` (add `-t "<name>"` to filter by test name)

Supabase credentials are required in `.env` (`SUPABASE_URL`, `SUPABASE_KEY`) — see README; the home page queries Supabase at render time, so `dev`/`build` fail without them.

## Architecture

Astro 6 site (React islands + Tailwind v4 + shadcn/Base UI) — a bilingual (`en`, `es`) "know your rights" page, deployed to Netlify.

**Content vs. UI strings are separate, per-locale sources that must stay in sync:**
- Long-form page body lives in `content/en.mdx` and `content/es.mdx`, loaded via the `content` collection (`src/content.config.ts`, glob loader). The entry id is the locale code; MDX can import React components (e.g. `<Callout>`).
- Short UI strings live in typed objects `src/i18n/en.ts` / `es.ts`; `Translations` is `typeof en`, so `es` must match `en`'s shape. Access via `getTranslations(locale)`.
- Adding a language means touching `src/constants/lang.ts`, `astro.config.mjs` (`i18n.locales`), both i18n and content files.

**Routing:** `src/pages/index.astro` serves the default locale (`en`, unprefixed); `src/pages/[locale]/index.astro` statically generates the alternate locales (`ALT_LANGUAGES`). Both just render `layouts/layout.astro` + `components/main.astro`, which pulls the MDX entry for `Astro.currentLocale`, builds the nav from the MDX `headings` plus an extra "resources" heading (`lib/links.ts`), then renders Hero → Nav → MDX → Resources → Footer.

**Heading IDs:** `plugins/normalize.ts` is a remark plugin that strips diacritics before slugging, so Spanish headings produce ASCII anchors. Nav links depend on these ids.

**Local resources (Supabase):** `components/resources.astro` queries the `community` table at build/render time to populate the city/state combobox (`components/search.tsx`, a `client:visible` island). On selection, `actions/getResources.ts` fetches `/api/resources?city=&state=` (`pages/api/resources.ts`, the only `prerender = false` route), which joins `resource` → `community` in Supabase. DB types are in `src/types/supabase.d.ts`.

**Build pipeline:** `astro.config.mjs` only enables the Netlify adapter when `NODE_ENV=production`. Post-processing integrations (`@critters-rs/astro` critical CSS, `astro-purgecss`) run on the built HTML, with `build.inlineStylesheets: "never"`.

## Conventions

- Import alias `@/` → `src/`. Imports in tests/components are grouped with `// Theirs` / `// Ours` comments.
- ESLint enforces double quotes, semicolons, trailing commas on multiline, and Tailwind class linting against `src/styles/global.css`.
- Astro component tests use `renderAstro()` from `src/tests/_utils.ts` (Astro Container API rendered into a happy-dom `div`) with Testing Library queries; `vitest.config.ts` uses `getViteConfig` so Astro/Vite config applies in tests.
